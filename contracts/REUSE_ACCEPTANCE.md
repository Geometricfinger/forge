# Frozen requirement-to-reuse acceptance — authored before implementation

The existing 100 workbench tests must remain byte-for-byte unchanged and pass.

Product workflow:
1. Start with real source-bound Hound observations in a saved discovery mission.
2. Freeze an immutable requirement contract and current candidate snapshot.
3. Group findings by real symbol or explicit source scope; never invent a function.
4. Distinguish observed API syntax, attributed reviewer statements, and executed tests.
5. Missing syntax observations are UNKNOWN, not proof of absence.
6. Exact API observations can satisfy only explicitly syntactic criteria, never behavior criteria.
7. Manual evidence cannot mark a behavior test executed. No field grants reuse/deployment permission.
8. Repeated evidence delivery is idempotent. Revisions require an exact current head; stale writers fail.
9. Review history survives process restart. Mutation of frozen records must be detected.
10. A changed candidate source/hash/profile makes an old case stale. Prior evidence stays visible.
11. Export contains contract, source lock, comparison, evidence trail and concrete missing steps.
12. No arbitrary source, shell command, model, installer or network action is executed by comparison.
13. A fixed, reviewed JSON-record reuse trial exercises actual first-party functions and tests before selection.
14. Positive and deliberately unsuitable candidates must remain distinguishable. Baseline-correct tests must not regress.
15. HTTP and CLI expose the same product decisions. Both deny malformed requests and unsupported authority.
16. Exact extracted package repeats tests and first-party workflow with consistent semantic outcomes.

Limitations: same-host operator is trusted; hashes do not authenticate truth or establish hostile-host isolation. No independent customer/agent benchmark is implied.
